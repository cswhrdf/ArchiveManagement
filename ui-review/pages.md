# 界面逐页评审

截图来自 `ui-review/capture.py`（一次性脚本，不改产品代码）：

```powershell
uv run python ui-review/capture.py empty      # 空库: 临时 root, 拍 01~04
uv run python ui-review/capture.py populated  # 有数据: dev-data 的副本, 拍 05~29
```

- **空库**一遍是全新临时目录（真的什么都没有），**有数据**一遍是 `dev-data` 整份复制到
  `ui-review/.tmp-dev-data/` 后跑的 —— 界面会把筛选/展示偏好写回 `home_state`，直接在
  `dev-data` 上跑等于改本地开发数据。脚本同时把联网补译名/补封面关掉了。
- 所有图都是**按窗口句柄**抓的（`tests/crash_capture.py` 同一套 `ImageGrab.grab(window=hwnd)`），
  被别的窗口盖住也不影响。
- **截图局限（影响下面若干条判断）**：按句柄抓只得到窗口**客户区**，看不到系统标题栏与窗口
  边框，所以"标题栏文案/图标/最大化按钮"这一项本轮没有评审；另外画面里看不出鼠标悬停态与
  动画过渡，悬停配色只能靠代码/历史判断。
- **两处状态是脚本注入的**：`11/12` 的启停表格（真实轮询要有游戏进程在跑才会出队列内容）、
  `17` 的快捷键录制中（真实录制要按住按键）。其余画面都是应用自己读出来的真实数据。

## 空库（01~04）

### 01-主页-海报视图-空库.png

- **位置**：主窗口 → 游戏主页 → 游戏库分区 → 海报展示（0 款游戏）
- **能做什么**：切列表/海报、切视图页签与筛选、批量导出、走右上角「+ 添加游戏」或「导入归档包…」，也可以切到「游戏发现」扫本机已安装的游戏。
- **看起来不对劲**：
  1. 空状态下右侧仍常驻一条**竖直滚动条**，而且拖不动 —— 视觉上在说"下面还有内容"。
  2. 空状态只有左上角两行小字（"游戏库还是空的。" + 一行提示），却占着约 1300×520 的深色卡片，密度低到像渲染失败；海报模式下尤其明显（连海报卡片的轮廓都没有）。
  3. 底部"共 0 款游戏 · 最近活跃 0 · 待处理 0 · 已归档 0"+"每页 30 / 上一页 / 第 1/1 页 / 下一页"整行照旧显示，"上一页/下一页"的禁用态与可用态底色几乎一样（都带浅色描边），看不出不能点。
  4. 顶栏「+ 添加游戏」是全站唯一的高亮绿按钮，与"打开详情"选中态、页签选中态同色系 —— 一个代表"主操作"、两个代表"当前状态"，语义混在一起。

### 02-主页-列表视图-空库.png

- **位置**：同上，换成列表展示（0 款游戏）
- **能做什么**：同 01，另外表头说明各列含义。
- **看起来不对劲**：
  1. 7 列表头（游戏/平台/存档位置/备份/最近备份/最近活动/状态）在**一条数据都没有**时仍然完整显示，紧接着就是空状态文案，表头像是"表格坏了"。
  2. 表头下方第一个数据行的位置直接压着空状态文案，两者之间没有留白，字号还比表头大，层级颠倒。

### 03-主页-游戏发现-空库.png

- **位置**：主窗口 → 游戏主页 → 游戏发现分区 → 探测结果页
- **能做什么**：点右上「重新扫描」扫本机（Steam/Epic 清单、Windows 注册表里的 GOG/Ubisoft、监控目录），用「待处理」下拉筛选，对选中的候选做导入/忽略/修正路径。
- **看起来不对劲**：
  1. 两行说明文字（"按当前平台可用的来源扫描本机已安装游戏…"）右端直接顶到右上角「待处理」下拉框的左边，文字与筛选控件挤在同一块区域里，没有分栏或留白。
  2. 右侧「导入为游戏 / 忽略 / 修正路径」三个按钮悬在筛选下拉正下方、贴着右边缘，而它们其实作用于"列表里选中的那一条"—— 列表里没有任何选中项时按钮仍在，看不出作用对象。
  3. 底部两组计数重复："监控目录 0 个 · 筛选 0 项 · 待处理 0 项"和"待处理 0 · 已导入 0 · 已忽略 0"分别在说同一批数。
  4. 空状态提示（"暂无探测结果, 点击页签右侧的「重新扫描」开始探测。"）用的是 11px 最弱灰，是全页对比度最低的文字，而它恰恰是唯一的行动指引。

### 04-主页-游戏启停-空库.png

- **位置**：主窗口 → 游戏主页 → 游戏启停分区（自动启停关闭）
- **能做什么**：看队列（顺序/游戏/状态/首次观察到/最近一次探测），点「刷新」重探，去设置里打开自动启停。
- **看起来不对劲**：
  1. 表格表头 + "暂无运行中的游戏。"同屏出现，与 01/02 是同一个毛病（空态与表头不互斥）。

  3. 说明文字里全角/半角混用：`在「设置 · 游戏启停」里打开开关后,这里会按启动顺序列出运行中的游戏。`——全角引号配半角逗号，且这行与上面的"自动启停已关闭"字号、颜色几乎一样，看不出哪个是标题、哪个是解释。
  4. 整页约 780px 的行高里只有 3 行内容，大面积空白（这一问题在有数据时更明显，见 11/12）。

## 有数据（05~29）

### 05-主页-海报视图.png

- **位置**：主窗口 → 游戏主页 → 游戏库 → 海报展示（3 款游戏，1 款选中）
- **能做什么**：点卡片选中/双击进详情，右上动作行（打开详情/立即备份/添加存档位置/修正路径/编辑标签/启用/归档），左「批量导出…」，底部翻页。
- **看起来不对劲**：
  1. 选中态的**绿色粗描边**只在海报卡片上出现（列表模式是整行浅绿底），两套选中语言不统一；而且选中卡片的绿与「+ 添加游戏」「打开详情」完全同色，"我选中了谁"和"哪里能点"分不开。
  2. 封面上的角标（"6 备份"/"0 备份"）与「无有效存档路径」这类状态文字**直接压在封面图**上，第一张封面上的游戏 logo 文字被角标盖住一半，可读性差（深色底+白字在浅色封面上勉强能看）。
  3. 无封面的"测试游戏"卡片用**超大号居中占位字**（"测试"），与其它卡片的信息密度完全不同，一张占位卡像是另一个组件。
  4. 卡片内名称最多两行、下方紧跟一行 11px 小字"最近活动 2026/09/24 00:35"；名称与元信息之间只有字号差异、没有留白，视觉上像同一段文字被截断。

| 导出/导入的**真实**流水线（进度、忙碌态、取消）       | 需要真的写出/读入归档包并让后台线程跑完；本轮只截了"选包之后"的冲突对话框（28/29），没有截进度提示与状态栏忙碌态。                                                                    |

| macOS / Linux 上的同一批页面                          | 本轮只在当前 Windows 机器上跑，`dev-data` 里的路径也全是 Windows 形态（`D:\...`）；跨平台的间距/字体差异仍要靠 CI 报告与布局用例覆盖。                                                |

     时 `winfo_ismapped()` 读到的是 `0`。旧实现拿它当初值 → 认为"已收起" → 内容装得下时
     `needed == shown`，于是**什么都不做**，那条滚动条就一直挂着。
  2. **`CTkScrollbar._draw()` 结尾那句 `update_idletasks()` 会把刚摘掉的滚动条映射回来**：画布每次
     滚动/尺寸变化都会回叫 `set()` → `_draw()` → 强制刷事件队列 → Tk 里排队的映射动作当场执行掉。
     实测该位置灰色像素 **3706 → 0**（按窗口句柄抓图后数颜色，同时用屏幕裁剪与 `winfo_containing`
     两条独立证据确认过"它真的画在屏幕上"）。
  修法：首次判定按"已显示"起算；收起改用 `grid_forget()`（同时清掉 CTk 记的最后一次几何调用，
  免得缩放/换肤时被重放回来）；给 `CTkScrollbar._draw` 去掉那句强制刷新
  （`widgets.apply_scrollbar_visibility_fix`）。守卫：`tests/integration/test_gui_scrollbars.py`
  四条真实控件用例 + `tests/unit/test_ui_widgets.py` 两条替身用例，逐条都验过"改坏就红"。
  完整定位手法与踩过的坑记在 `.github/instructions/ctk-scrollbar-twitch.instructions.md`。
