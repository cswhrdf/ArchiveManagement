# 08 自动启停与监控队列

## 它解决什么问题

"当前启用的那一款"决定了**全局快捷键**与**定时备份**作用在哪个游戏上（全局至多一款启用）。手动切换麻烦，所以有了这个功能：**软件盯着进程表，谁先被观察到运行，就把启用态切给谁**。

开关位置：**设置窗口 →「游戏启停」面板 →「按进程自动启停」**（默认关闭）。

## 规则

- **监控范围 = 当前导入的全部游戏里"能备份"的那些**（未归档，且**至少关联了一个存档位置**）。"待处理"的游戏不参与 —— 它们本来就没有可备份的内容。
- 一次轮询**只枚举一次进程表**：谁先被观察到运行，谁就接管启用态；**接管之后其他游戏启动不再抢**。
- 所有被观察到运行的游戏都**按启动顺序登记成队列**，展示在主页的「游戏启停」分区里。
- 当前监控的那一款**退出**时，自动切到**队列里第一条仍在运行**的那款继续监控；队列清空（都退出了）才把启用态收回来。
- **手动优先**：
  - 手动**启用**某款 = 把它设为监控对象并移到队首，同时**恢复自动接管**（哪怕它此刻还没运行，也不会被队列里正在跑的其它游戏顶掉）；
  - 手动**停用**某款 = 只要它还在运行就绝不会被自动启用回来（观察到它退出即解除）；停用的正是当前监控对象时，**本批次不再自动接管**，直到队列清空或你再手动启用任意一款。

## 自适应轮询

| 场景                                                   | 间隔                                          |
| ------------------------------------------------------ | --------------------------------------------- |
| 队列为空（没人在玩）                                   | **5 秒**（尽快发现"游戏启动了"）              |
| 队列非空                                               | 每轮放慢一档：5 → 8 → 12 → 16 → **20 秒**封顶 |
| 队列重新清空                                           | 立刻回到 5 秒                                 |
| 你手动操作（开开关、启停、分页里刷新或"设为监控对象"） | 计数清零并**立即再探一次**                    |

代价要说清楚：**退出的发现最多晚 20 秒**（回落与"全部退出后停用"跟着晚）。这是"启动快、退出稍慢"的取舍。

## 界面

「游戏启停」分区里有一行摘要（当前监控对象 + 开关状态 + "手动暂停中 / 等待游戏启动 / N 款名称冲突"）与队列列表（序号 = 启动顺序、游戏名、状态、首次观察到时间、最近一次探测时间），每行可以「设为监控对象」或「打开详情」。

- **不列"已结束"的历史条目**：退出即出队，这个列表只表达"现在在跑什么、顺序如何、谁在被监控"。
- 状态栏只在**真的发生变化**时提示：接管「X」/「X」退出后切到「Y」/ 全部退出已停用 / 已暂停本批次的自动接管。

## 保守优先（拿不准就不动）

- **只在亲眼见过它运行之后**，才允许因为"不再运行"而停用 —— 否则"刚启用、游戏还在启动中"会被下一轮误停用。
- 进程枚举失败（无法确认）、名字匹配不上 → **什么都不做**，也**不会**改掉"见过它运行"的记录。
- **名称冲突**：跨多款游戏共享的名字（例如一款叫 `Wilds`、另一款 `OuterWilds`）整条丢弃，一个进程名只有归属唯一时才算数；冲突导致一款都没法判断时同样什么都不做，并在分页上显示"N 款游戏名称冲突，已暂停自动判断"。
- 开关关闭、或库里没有任何可监控的游戏时，**一次进程表都不枚举**。
