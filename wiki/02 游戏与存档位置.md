# 02 游戏与存档位置

## 录入游戏

- 顶栏 **“+ 添加游戏”**：填名称即可新建一条游戏记录（新建的游戏默认**停用**）。
- 或者从 **游戏发现** 分区扫描本机平台客户端，把发现的游戏"导入为游戏"（见 [[07 游戏发现与平台支持]]）。
- 录入时的名称会单独保存为「原始名称」：之后改名不会丢掉它，概要区会同时显示"原始名称"与备份目录名，方便在磁盘上对照。

## 添加存档位置

在游戏的 **游戏设置** 里添加「原始存档位置」，支持两种类型：

- **目录**：最常见，整个目录会被快照。
- **单个文件**：某些游戏的存档就是一个文件。

录入时做这些校验：路径存在、类型对得上（目录/文件）、可读、以及**重复路径检测**；不通过的路径不会被静默接受。

一个游戏可以有**多个存档位置**，其中一个是**主位置**；备份会把所有位置一起快照并记下各自来源，恢复时按快照记录的来源逐个写回。

## 路径健康状态

每个位置都会显示实时状态（可用 / 不存在 / 不是目录 / 不可读 / 高风险）。主页的状态标签会在路径不可用时标红，这类游戏会被归到「待处理」。

被拒绝的危险位置包括：**盘符根目录**、**用户主目录**、**应用自己的备份目录**（及其子目录、包含它的祖先目录），以及**整个游戏安装目录**。注意最后一条的边界：

- 候选**就是**安装目录、或**包含**安装目录 → 危险，拒绝；
- `<安装目录>\saves` 这类**子目录** → 合法，放行（很多游戏的存档确实放在安装目录里）。

盘符路径的大小写不敏感：`D:\Steam` 与 `d:\steam` 视为同一处。

## 原始位置 vs 备份位置

界面上两处永远分开显示：

- **原始存档位置**：游戏自己读写的地方，只有"恢复"与"删除原始存档位置"会动它；
- **备份目录**：应用自管的存储（目录名形如 `<游戏名称>-<短哈希>`），只由备份逻辑写入。

备份目录名在首次备份时确定并写进数据库，**之后改名或增删存档位置都不会搬动已有备份**；短哈希由"名称 + 全部存档路径"推导，用来区分同名游戏。

## 修改与删除

- 改名、改位置、启用/停用都在游戏设置里，改动即时生效。
- **归档**是"先别管它"：归档会停用该游戏并暂停它的定时备份，只保留"删除游戏 / 导出游戏 / 取消归档 / 打开详情"四件事。
- **删除游戏**在游戏管理窗口里（唯一入口），顺序是**先把这款游戏的配置与全部备份导出成一份归档包，再删除游戏记录与存档位置**：确认框里会写清这份包会落在哪里（备份目录旁边的 `exports` 目录），导出失败时什么都不会删。备份目录里的备份文件保留。
- 删掉**库里最后一款**游戏时界面会自己回到「游戏主页」（详情页是围绕某一款游戏建的，游戏没了就不该把这一页留在屏幕上），主页显示"还没有游戏"并给出「去游戏发现」。

## 进程名候选

「游戏设置」窗口里有一节**进程名候选**：这是自动启停用来认出游戏进程的名单（见 [[08 自动启停与监控队列]]）。导入游戏时会从安装目录自动收集（目录名与主程序名）；中文译名与进程名对不上时，可以在这里手动**添加**或**移除**候选。

- 这一节**默认是收起的**（刚打开游戏设置时只看到一行标题）：点标题右侧的「展开进程名候选」才会展开，展开后再点「收起进程名候选」就收回去。窗口高度会跟着变，不用手动拉。
- 一款游戏最多保留 5 条候选，新的候选在下一次轮询时生效。
- 名字里不能包含逗号（它是名单的存储分隔符）；去掉后缀与分隔符后不足 3 个字符的名字也无法用于匹配。这类输入会被直接拒绝并说明原因，不会悄悄丢弃。
- 已归档的游戏不参与自动启停，这一节也随之置灰。
