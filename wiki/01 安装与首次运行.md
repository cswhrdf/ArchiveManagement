# 01 安装与首次运行

## 环境要求

- **Python 3.12 及以上**（仓库只用 3.12 验证）。
- 依赖用 [uv](https://docs.astral.sh/uv/) 管理，不需要手动 `pip install`。
- Windows 是首要发布平台；Linux 需要图形环境（有显示服务的桌面，或 `xvfb` 之类的虚拟显示）；macOS 未做实机测试。

## 启动方式

```bash
uv sync                                  # 首次：创建虚拟环境并装齐依赖
uv run python -m archive_management gui  # 启动图形界面
```

其它常用入口：

```bash
uv run python -m archive_management init   # 只初始化数据目录与数据库
uv run python -m archive_management doctor # 打印平台信息、目录位置与探测可用性
```

不带子命令直接运行时等价于 `init`。

## 数据放在哪里

默认走系统标准目录（由 `platformdirs` 解析）：

| 内容                        | Windows                             | Linux                                                           | macOS                                              |
| --------------------------- | ----------------------------------- | --------------------------------------------------------------- | -------------------------------------------------- |
| 数据 / 配置 / 数据库 / 备份 | `%LOCALAPPDATA%\ArchiveManagement\` | `$XDG_DATA_HOME/ArchiveManagement`（通常是 `~/.local/share/…`） | `~/Library/Application Support/ArchiveManagement/` |
| 日志                        | 同上                                | 同上                                                            | `~/Library/Logs/ArchiveManagement/`                |

`doctor` 会把这些路径打印出来，想知道"东西到底在哪"时直接看它。

## 便携模式（`--root`）

给任意命令加上 `--root <目录>`，**全部数据都收敛到那一个目录**（配置、数据库、日志、备份、缓存）：

```bash
uv run python -m archive_management gui --root .\dev-data
```

适合放进 U 盘随身携带，或开发时把数据与真实环境隔开。

## 首次运行会看到什么

- 首次启动是**空库**：主页三个分区（游戏库 / 游戏发现 / 游戏启停）里都没有内容，界面会给出各分区自己的空状态提示，而不是一片空白。
- 两种录入游戏的方式：顶栏的 **“+ 添加游戏”**（手动录入），或者去 **游戏发现** 分区扫描本机已安装的游戏后导入。
- 录入游戏后，**必须为它添加至少一个“原始存档位置”**，备份、定时任务与自动启停才会对这款游戏生效 —— 没有存档位置时它会被归到「待处理」，主页会明确显示"无有效存档路径"。
- 新建的游戏默认是**停用**状态：全局至多一款游戏处于启用状态，全局快捷键与定时备份都只作用于那一款。启用入口在主页的「启用/停用」按钮或游戏设置里，也可以交给 [[08 自动启停与监控队列]]。
