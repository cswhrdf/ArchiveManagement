# 03 备份、分支与时间线

## 一次备份是怎么落地的

- 先在同一级写**临时目录**，逐文件复制并计算 SHA-256，复制完再复核一遍；
- 全部成功后才**原子改名**成正式快照；
- 目标目录已存在时**直接失败，绝不覆盖已有备份**；失败或取消不会留下"看起来像完整备份"的半成品节点。

每个快照都记录内容哈希与文件清单，列表里的「已验证」标记来自清单的实际校验。

## 三种新建备份的方式

| 方式           | 位置                                  | 说明                                     |
| -------------- | ------------------------------------- | ---------------------------------------- |
| 立即创建备份   | 详情页工具栏 / 全局快捷键 `Win+Alt+S` | 以**当前节点**为父节点向下保存一次       |
| 从此处创建分支 | 选中任意节点                          | 以该节点为父节点分出新分支，并记录分支名 |
| 定时自动备份   | 游戏设置 → 定时备份                   | 见 [[05 定时任务与全局快捷键]]           |

快捷键只对**当前启用的那一款**游戏生效（停用或已归档的游戏只给一条提示），避免误按到不相关的游戏上。

## 内容没变就不重复备份

每次备份（手动 / 分支 / 自动 / 恢复前安全点）之前都会先与当前节点做内容比对：

- 存档一点没变 → **手动点击**弹窗告知"存档没有变化"；**自动备份**静默跳过（只在日志里留 DEBUG 记录）；
- 变了才产生新快照 —— 因此时间线里不会有大量内容完全相同的节点。

## 两个视图

- **分支树**（默认）：按层级缩进展示手工分支关系；自动备份只显示**最新一份**，不把树撑长。
- **时间线**：按时间倒序展示**全部**备份，并标明各自所属分支；恢复前安全点（`is_safety`）**只在这里出现**，不占分支树的位置。

工具栏的来源筛选可以只看某一类节点（手动备份 / 自动备份 / 恢复前安全点）。每个节点还能「重命名 / 描述」（描述最多 200 字）。

## 删除备份

按分支树决定处理方式：

- 同一线路上的节点被删除 → 后续节点**自动上移**，不会变成孤儿；
- 删除**分支根节点** → 先提示"会连带删除该分支下的全部备份"，确认后整棵树一并删除。

## 备份目录与命名

- 备份根目录下按游戏分目录：`<游戏名称>-<短哈希>`，例如 `OuterWilds-3f9a2c1b`。
- 名称部分保留中文、替换文件系统的非法字符；短哈希区分同名游戏。
- 该目录名在首次备份时确定后**不再变化**，改游戏名不会搬动已有备份。

把备份带到另一台机器、或从别处的归档文件导入成新的游戏，见 [[11 导入与导出]]。
