# 功能说明：备份、分支、恢复与日志

本文档说明核心行为与约定。游戏库、主页与本地游戏发现见 [library.md](library.md)，
全局快捷键见 [hotkeys.md](hotkeys.md)，平台差异见 [platforms.md](platforms.md)。

## 界面结构

- 界面由**顶栏 + 内容区 + 底部状态条**组成。顶栏左侧是品牌与"← 游戏主页"（只在某个游戏的详情页显示），右侧是三个全局入口：**+ 添加游**、**定时任务**、**设置**。
- "定时任务"与"设置"共用一个窗口位置：**重复点击同一个入口只会把已打开的窗口提到前台**，再点另一个会提示先关闭当前窗口，不会同时开出多个配置窗口。
- 内容区有两页：**游戏主页**（打开软件后的默认页）与**游戏详情**。在主页双击某一行、点"打开详情"，或从左侧游戏列表选中游戏即可进入详"← 游戏主页"随时返回。
- 右下角的状态条显示备份服务状态（服务正常 + 备份存储当前占用），并在数据变化后刷新；左侧显示最近一次操作反馈。
- **数据瞬时读不出来时界面不会崩**：启动加载（游戏主页 / 游戏发现）与轮询在读取失败时保留上一次的画面，并在反馈区列出原因（如“读取数据失败: unsupported file format”），下一次刷新会自动恢复。
- **超长游戏名不会把界面撑坏**：详情页标题与概要卡里的名称**按控件当前宽度**裁剪（窗口变宽就多显示几个字），最多折两行并补省略号（否则会把下面的内容整排推下去，或把右侧按钮挤出可视范围）；列表与海报同样有上限。需要看完整名称时打开该游戏的"游戏设置/重命名"对话框。

## 游戏与存档位置

- 用顶栏的"+ 添加游戏"录入游戏或游戏发现中导入已发现的游戏；在游戏设置里为该游戏添加"原始存档位置"，支持选择目录或文件，记录规范化绝对路径，并对可用性（存在、类型、可读）与重复路径做校验。
- **原始位置与应用管理的备份目录分开展示**，避免把两者搞混而误操作。
- 单个游戏可以有多个存档位置，其中一个是主位置；恢复时按快照记录的来源逐个写回。

## 备份、分支与时间线

- **"立即创建备份"**（或全局快捷键 `Win+Alt+S`）把当前存档位置复制为应用自有存储中的一次快照：先写入同级的临时目录，逐文件计算 SHA-256 并复核，全部成功后才原子改名为正式快照；目标已存在时直接失败，**绝不覆盖已有备份**，失败或取消不会留下半成品节点。
- 快捷键统一在"设置"中查看与修改。
- **只有当前启用的那款游戏会响应快捷键与定时备份**：全局至多一款游戏处于启用状态（新建的游戏默认停用），可在主页的「启用/停用」按钮或游戏设置里切换，启用另一款时原来那款会被自动停用。想让软件跟着游戏进程自动切换，见下面的「游戏启用与按进程自动启停」。
- **归档只保留四件事**：删除游戏、导出游戏、取消归档与打开详情；归档会同时停用该游戏并暂停它的定时备份，「删除游戏」仍在游戏管理窗口里（此时窗口内其余按钮全部置灰）。
- **内容没变就不重复备份**：每次备份（手动/分支/自动）之前都会先与当前节点做内容比对，存档一点没变时不产生新备份。手动点击时弹窗告知"存档没有变化"，自动备份静默跳过（只在日志里留 DEBUG 记录），恢复前的安全点同理跳过。
- **备份目录按游戏名称命名**：目录名为 `<游戏名称>-<短哈希>`，例如 `OuterWilds-3f9a2c1b`。名称部分由识别到的游戏名称规范化而来（保留中文，替换文件系统非法字符），短哈希由"名称 + 全部存档路径"推导，用来区分同名游戏。目录名在首次备份时确定并记录在数据库中（见 `games.storage_key`），之后改名或增删存档位置都不会搬动已有备份。
- 录入时的原始名称单独保留（`games.original_name`）：改过名后概要区会额外显示"原始名称"与"备份目录"，方便在磁盘上对照找到对应目录。
- **"从此处创建分支"** 以选中节点为父节点并记录分支名（默认文案为本地化的"分支"/`Branch`，英文环境自动用英文）；**"重命名 / 描述"** 可修改备份名称与最多 200 字的描述。
- **"删除备份"按分支树决定处理方式**：同一线路上的节点被删除时后续节点自动上移；删除分支根节点会先提示将连带删除其分支下的全部备份，用户确认后整棵树一并删除。
- 新建的手动备份带默认名称"手动备份"（自动备份为"自动备份"）直接显示在标题列，**内容摘要默认为空**，需要说明时再用"重命名 / 描述"补充。
- 默认展示**分支树**（按层级缩进，自动备份只显示最新一份），可切到**时间线**查看全部备份及其所属分支。 <!-- TODO: 分支树功能要改为树形结构 -->
- 每个备份节点都记录内容哈希与文件清单，列表中的"已验证"标记来自快照清单的实际校验。

## 定时与自动备份

- 定时备份**按游戏独立配置**（周期如 `30m` / `2h` / `1d` 与自动备份保留份数，默认 3 份）：主入口是"游戏设置 → 定时备份"，工作区的"定时任务"用于统一查看与管理。周期留空即取消。
- 自动备份超出保留份数时最旧的一份连同快照被清理，且不会让后续节点变成孤儿。
- 定时任务的配置保存在数据库里，因此**关闭软件再打开会自动继续生效**（周期、启用状态与保留份数都不会丢，不需要重新设置）；每次执行后会重新读取后端排出的**下次运行时间**，即使本次因"存档未变化"被跳过，界面上的下次运行与概要卡也会刷新。
- **未配置存档位置的游戏无法创建定时任务**（没有可备份的内容）：新增前就会拦下并提示原因，后端也会再校验一次。
- 右侧的"任务状态"卡展示当前操作进度、下次运行时间与备份目标（长文案自动换行）。
- 顶栏的"定时任务"打开全局任务窗口：**只列出已配置定时备份的游戏**，每条标明来自哪个游戏、下次运行时间、当前设置的周期与已保留的自动备份份数，并可编辑、暂停/继续与删除；"新增任务"先弹出可**输入关键字筛选**的游戏选择框（弹窗里注明推荐去单个游戏的编辑区配置）。

## 恢复

- 恢复对话框在**同一个窗口**内展示快照规模、写回目标与风险提示，并可勾选"恢复前先创建安全点"（默认勾选，便于回到恢复前的状态。恢复安全的的创建任然遵守创建备份的规则，当前存档与当前节点做内容比对相同则不重复备份）。
- **"恢复到此节点"** 把选中的备份写回原始存档位置，并把**当前节点**切换过去（带 ● 标记），之后的"向下保存"与"创建分支"都从该节点重新开始。
- 恢复前会深度校验快照清单、检查目标路径是否可写（盘符根目录、用户主目录、应用备份目录一律拒绝）并探测游戏进程；检测到游戏在运行时会提示风险并要求明确确认。
- 写回过程先在目标同级的 `.restore-*` 暂存目录里重建内容（逐文件核对哈希），再用改名原子替换；替换失败会把原内容改名回滚。存档里被删掉的文件与目录会被重新建出来。
- **快照之外的文件在恢复后原样保留**（恢复是"覆盖"而不是"镜像"）：需要回到恢复前的状态时，从时间线恢复"恢复前安全点"即可。
- 快照的清单路径按**不可信输入**处理：绝对路径与 `..` 越界条目直接拒绝；符号链接只重建链接本身，环境不允许时记为跳过项而不是中断恢复。
- "恢复前安全点"是标记为 `is_safety` 的备份，**只出现在时间线视图**，不占用分支树的层级位置；用工具栏的来源筛选选择"恢复前安全点"可以单独查看它们。

## 原始存档目录管理

- **"删除原始存档位置"** 把磁盘上的原始目录移入**系统回收站**（绝不永久删除），删除前要求输入游戏名称确认，并显示目标路径、文件数量与总体积。
- 盘符根目录、用户主目录与备份目录（及其子目录、包含备份目录的祖先目录）会被拒绝，磁盘上不会发生任何改动。
- 删除的是主位置时，主标记会自动交给下一个位置；被删除的只是磁盘内容与位置记录，应用管理的备份不受影响。

## 界面语言与游戏译名

- **设置里的「界面语言」**（简体中文 / English）切换后界面会立即用新语言**整体重建**，选择写回配置文件，重启后仍是该语言。
- **游戏名按当前语言探测**：**启动时**、扫描“游戏发现”时、导入游戏后以及切换语言时，各在后台问一次平台该语言的译名（Steam 用公开的商店接口，无凭据）。**探测结果页**直接在那一行显示译名，并把探测到的原名放在括号里（如 `星露谷物语 (Stardew Valley)`）；已导入的游戏则把译名改写进游戏记录，主页/详情/备份目录名随之变化。**该语言没有译文、离线或限流时一律保留探测到的原名**，不猜也不翻。改过名的游戏永远不会被译名覆盖 —— 用户起的名字优先。
- 译名按 `AppID + 语言` 缓存在应用缓存目录（`game-names.json`，**单行紧凑 JSON、只给程序读**：不写缩进、换行与分隔空格；名称里为了排版加的换行/制表符/连续空格也会被归一成单个空格，历史条目在读出时就已归一）：启动补探测、扫描补探测都只对**当前语言缺条目**的游戏联网（有缓存就直接复用，离线也不影响启动）。**切换语言会重新探测一次**（忽略缓存），因此中英切换后名称会跟着变；删除游戏时会连译名缓存一起清掉。

## 游戏启用与按进程自动启停

- **“启用”表示“现在在玩这一款”**：全局至多一款游戏处于启用态，全局快捷键与定时备份只对它生效；启用另一款会自动把原来那款停用，归档的游戏不能启用。新建游戏默认**停用**，由用户明确选择。
- 设置窗口「游戏启停」面板里的**「按进程自动启停」开关（默认关闭）**打开后，软件会监控**当前导入的全部游戏**（归档的不参与；**没有关联存档位置的“待处理”游戏也不参与** —— 它没有可备份的内容，接管它没有意义；一次轮询只枚举一次进程表），并把观察到的运行按**启动顺序**登记成队列：
  - 还没有监控对象时，**谁先被观察到运行就接管谁**；
  - **接管之后其他游戏启动不会把它抢走**，只进队列；
  - 当前监控的那一款**退出后**，自动切到队列里**第一条仍在运行**的游戏；
  - 队列里没有可接的了（都退出了）→ 收回启用态；它下次再启动会被重新接管 —— 因此只需在软件里启用一次。
- 主页的**「游戏启停」分区**展示这个队列（序号、游戏名、状态[监控中 / 运行中 / 已暂停自动接管]、首次观察到与最近一次探测的时间），每行可以把该款**设为监控对象**（等于手动启用它）或打开详情。
- **轮询间隔是自适应的**：队列为空时用最快档（5 秒，尽快发现“游戏启动了”）；有游戏在运行时逐档放慢到 20 秒上限（代价是退出的发现最多晚 20 秒）。开关打开、手动启用/停用、进入或刷新启停分区都会把间隔退回最快档并**立即再探一次**。
- **它是保守的**：只有在**亲眼见过某一款运行之后**才会因为“不再运行”而停用 —— 否则“刚启用、游戏还在启动中”会被当成“已经退出”；**无法确认**（进程表枚举失败）或名字匹配不上（全是中文、过短）时一律什么都不做。中文译名对不上进程名时靠录入时识别到的**原始名称**兜底（如界面显示“星露谷物语”，进程是 `StardewValley.exe`）。
- **全库匹配要先解决“这个进程名是谁的”**：同名或互相包含的候选名（如 `Wilds` 与 `Outer Wilds`）以及一个进程名同时指向两款游戏的情况一律**整条丢弃**，宁可不判断；被丢弃的名称数量会显示在启停分区上，改名或停用其中一款即可恢复判断。
- **手动调整始终优先**：手动启用某款会把它设为监控对象并移到队首（它还没起来也不会被队列里的其它游戏顶掉）；手动停用某款会让它进入**抑制**（只要它还在运行就不会被自动启用，退出即解除），停用的若是当前监控对象，则**这一批不再自动接管**，直到所有游戏都退出、或用户手动启用任意一款。
- 状态与队列都存在数据库里（`activation_state` 单行表 + `activation_runs` 队列表），因此重启软件后队列顺序与“还没启动 / 已经退出”的判断都不会丢；开关本身写在 `config.json` 的 `activation` 段。
- 排查“为什么没跟着切”：打开设置里的「启用调试日志」，日志里每一次判断都会记一条 `game.auto_activation`（原因、监控对象、在运行的款数、入队/出队条数、名称冲突数、被启用/停用的是谁）。

## 操作日志

- 所有用户操作都写入日志目录下的 `archive-management.log`（**不落数据库**）：备份/分支/恢复/删除等高风险操作用 INFO，主题切换、视图切换、筛选、选中这类基础操作用 DEBUG（**默认不写入**，见下）。
- 默认只记录 INFO 及以上的高风险操作（控制台与日志文件都是）；设置窗口「日志」面板里的**「启用调试日志」开关（默认关闭）**打开后，DEBUG 级基础操作也会写进日志，适合排查问题；加 `--verbose`（或 `gui --verbose`）则在本次启动时直接打开调试日志。
- 日志采用滚动文件（单文件上限 100 MB，保留 5 份；上限与保留份数可在 `config.json` 的
  `logging` 段落里调整），并且不记录凭据、文件内容或完整敏感路径：路径字段统一用
  `redacted_path()` 脱敏为"父目录名/条目名"。
