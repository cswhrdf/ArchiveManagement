## 游戏主页（游戏库分区）

**原文案**（曾显示在主页顶部页签右侧，`home.hint`，已从界面移除）：集中查看全部游戏并按状态筛选: 待处理 = 还没有配置存档位置或存档路径已失效。同一时刻只有一款游戏处于启用状态, 快捷键与定时备份只对启用的游戏生效; 归档后只保留删除、导出、取消归档与打开详情。

**为什么移出**：这段说明挤在页签右边，窗口不宽时左侧文字会被裁掉；页面本身应当清爽，规则类说明更适合放在文档/帮助里。

**要点整理**（wiki 版建议按这三条展开）：

- **待处理**：还没有配置存档位置，或者已有的存档路径已失效（迁移了游戏目录、删掉了存档文件夹时会出现）。
- **同一时刻只有一款游戏启用**：全局快捷键与定时备份只对启用的游戏生效；切换到另一款启用时，原来那款会自动停用。
- **归档**：归档的游戏只保留"删除游戏、导出游戏、取消归档、打开详情"四项操作，其它操作入口全部收起。

## 下拉框展开(2026-10-02)

下拉不再是 CustomTkinter 自带的那张 `tk.Menu`(Tk 菜单没有"最大高度"选项, 内容多会一路撑出软件窗口), 而是自建浮层(见 `ui/dropdown.py`):

- **最多 10 行**, 再多加滚动条 —— 内容永远不撑出窗口;
- **按位置决定方向**: 下方放得下往下展开, 放不下而上方放得下就向上; 两边都不够时取空间大的一侧, 并把行数压到放得下的行数;
- 宽度至少与控件同宽, 内容更宽就跟着放宽, 但不越出窗口右边界;
- 当前值打开即高亮并滚到可见; 点一行 = 选中 + 收起; 点窗口别处 / Esc / 再点箭头 / 换一个下拉都会收起。

浮层用原生 `tk` 控件画(临时层不在 CTk 窗口链上), 颜色仍取自控件所在窗口的调色板。它不用 `<FocusOut>` 收起: `overrideredirect` 的临时窗口抢到焦点后可能被立刻还回去, 那样会"一开就收"。

补充(2026-10-03): 超出上限时右侧会立一条**看得见**的滚动条 —— 滑块用 `text_muted`、轨道用 `panel`(与轨道对比度 ≥ 3:1), 而不是 CTk 滚动条那一档暗色。浮层上的暗色滑块看着就像"没有滚动条", 用户会以为后面没内容了。另外滚动条必须与列表**同容器**且在列表**之前** 占位, 否则会被 `expand` 的列表吃光, 分到 0 宽/0 高。

再补充(2026-10-03): 滚动条直接换成 CustomTkinter 原生的 `CTkScrollbar`(形状/圆角/悬停/宽度都与软件里其它滚动条一致), 不再自建 —— 它在普通 `tk` 临时窗口里也能拿到正确的 DPI 缩放。颜色仍按浮层自己的调色板取(底色 `panel`、滑块 `text_muted`), 保证"看得出有滚动条"。

另: 宿主窗口被最小化/隐藏时浮层会一起收起(接了宿主的 `<Unmap>` / `<Iconify>`)—— 它是独立窗口, 不然会飘在屏幕原处。

再补充(2026-10-03, 附图反馈): 浮层现在是**宿主窗口的附属窗口**(`transient`), 不再用 `-topmost` —— 所以点击别的程序时它会随本软件一起沉下去, 不会永远盖在最前面; 最小化本软件时它也会跟着消失。窗口被移动/改尺寸时浮层**跟着控件重算位置**(不再停在旧坐标上盖住旁边的程序)。 "能不能和原生组件结合"这条走不通: 原生下拉是 `tk.Menu`, 而 Tk 菜单没有"最大高度"这个选项, 限高 + 滚动条只能靠自建浮层(`ui/dropdown.py`)。

再补充(2026-10-03): 列表**装得下**的时候滚轮不起作用 —— 之前滚轮会把只有四项的"每页"滚走一行, 最上面那项被滚出视野、底下空出一行(附图反馈)。装得下就不该有"滚动"这回事; 真的超过上限、右侧立起滚动条时才让滚轮/滚动条生效。打开时另外把视图归零一次, 免得构建期(当时列表只有一行高) 留下偏移。

再补充(2026-10-03, macOS CI 实测): 两条**只在 macOS 上看得出来**的差异已经处理掉。①macOS 给无边框(override-redirect)窗口的 `-topmost` 默认值就是 1(Windows 上是 0), 于是"不盖住别的软件"这条在 macOS 上其实没成立 —— 现在 `_build` 里显式写一次 `-topmost False`, 两个平台读数与行为一致。②最小化/`withdraw` 的那一刻不能**当场**销毁浮层: 那会在窗口管理器处理映射变化的回调里销毁一个无边框附属窗口, macOS 上直接段错误(那一次分片就是这么死的), 现在用 `after_idle` 推到下一拍再收。

再补充(2026-10-30): 两处滚动手脚修掉 —— ①浮层高度改按 **Listbox 自己的请求高度**写, 且构建时就用"两档请求高度的差值"量出真行高(估的行高取整后与它实排的行距有亚像素差, 乘十行就差出小半行, 尾行被窗沿裁成一条读不出字的窄带, 看着像"多了一条空白选项"; 实测估 15px/行、实排 ~15.3px/行, 150px 窗口只装 9.x 行)。②当前值超出首屏时不再用 `see()` 最小滚动(它把选中项贴在视野**底边**, 开头几行被滚出视野 —— 用户反馈"选了靠下的选项后下拉框自动向下滚动, 遮住了第一个选项"), 改成"以选中项为第一行往下排", 与 Windows 原生下拉一致; 首屏装得下时视图钉回最上。

## 弹窗居中(2026-10-03)

弹窗(游戏详情、游戏设置等)的中心对准**主窗口**的中心 —— 用户反馈过"软件启动后第一次打开游戏设置, 窗口不在软件中间而偏右"。原因不是弹窗自己量错了, 而是那一刻**主窗口还没落地**: 它还没被映射, 尺寸读出来是布局前的占位值(实测 200, 真实值是 1500), 按它算居中就偏出几百像素, 而且之后再没有人重算。


## 设置面板的成段说明(2026-10-30)

设置窗口原来每个面板标题下都挂一条成段说明(快捷键面板末尾还有一条录制规则、"记住窗口"开关下还有一条), 一屏下来说明文字比设置项还多。现在**每个设置项只留名称**(面板标题、开关文字、下拉框), 成段说明全部移出, 对应 i18n 键一并删除(中英两份同删)。各条的现行行为在 docs/ 里已有记载, wiki 后续按每条标注的页面补写。

- **外观**(`settings.appearance_hint`,「外观」标题下): 在浅色与深色主题之间切换, 立即生效。→ [features.md](features.md)「键盘操作与可读性」; wiki 建议补到「09 配置文件与日志」。
- **界面语言**(`settings.language_hint`): 切换后界面立即用新语言重建, 并按新语言重新探测游戏译名。→ [features.md](features.md)「界面语言与游戏译名」; wiki「09 配置文件与日志」。
- **调试日志**(`settings.logging_hint`): 关闭时只记 INFO 及以上; 开启后 DEBUG 级操作也写进日志。→ [features.md](features.md)「操作日志」; wiki「09 配置文件与日志」。
- **记住窗口大小与位置**(`settings.remember_window_hint`,开关下方): 关闭后下次启动用默认大小; 已经记下的位置与大小会从配置里清除。→ [features.md](features.md)「启动与单实例」; wiki「09 配置文件与日志」。
- **按进程自动启停**(`settings.activation_hint`): 开启后按进程自动切换启用的游戏; 手动启停优先, 不会被自动改回去。→ [features.md](features.md)「游戏启用与按进程自动启停」; wiki「08 自动启停与监控队列」。
- **备份校验方式**(`settings.verification_hint`,最长的一条): sha256 逐文件比对内容哈希, 严格但要把快照完整读一遍; 仅校验名称只看清单里的名称与大小, 快但查不出内容被改过。随时可切, 切换只影响校验, 不影响已有备份。→ [features.md](features.md)「备份、分支与时间线」; wiki「03 备份-分支与时间线」。
- **全局快捷键**(`settings.shortcut_hint`,面板末尾): 点右侧按键后按下新组合键: 需含 Win、Ctrl、Alt 或 Shift 之一与至少一个字母键(数字键会与系统快捷键冲突, 不支持)。→ [hotkeys.md](hotkeys.md)「自定义组合键」; wiki「05 定时任务与全局快捷键」。

为什么移出: 设置项的**名称加当前值**(开关位置、下拉框内容、「当前主题: X」这类状态行)已经说明了它是什么; 代价与规则属于"读一次就够"的内容, 放在文档里按需查即可, 不必每次打开设置都陪读一遍(与「游戏主页」那条 `home.hint` 同一理由)。快捷键面板保留**录制中**的瞬时提示与按错键时的具体原因(`hotkey.err_*`), 只移走常驻的规则句; 「记住窗口」开关下那行改为平时留空的错误行, 应用失败时仍会把原因写出来。
现在的做法: 弹窗建好后照看主窗口一小会儿(几十毫秒一轮, 有上限), 尺寸/位置一变就跟着重算居中; 主窗口落地且几何稳定后立即停手。热路径(软件已经打开)下位置一次就算对, 复查只是空转 —— 用户看不到任何跳动。不"先睡一会儿再校一次"是因为主窗口什么时候落地由窗口管理器决定, 固定时长要么不够要么白等。
