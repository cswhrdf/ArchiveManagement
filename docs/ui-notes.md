## 游戏主页（游戏库分区）

**原文案**（曾显示在主页顶部页签右侧，`home.hint`，已从界面移除）：集中查看全部游戏并按状态筛选: 待处理 = 还没有配置存档位置或存档路径已失效。同一时刻只有一款游戏处于启用状态, 快捷键与定时备份只对启用的游戏生效; 归档后只保留删除、导出、取消归档与打开详情。

**为什么移出**：这段说明挤在页签右边，窗口不宽时左侧文字会被裁掉；页面本身应当清爽，规则类说明更适合放在文档/帮助里。

**要点整理**（wiki 版建议按这三条展开）：

- **待处理**：还没有配置存档位置，或者已有的存档路径已失效（迁移了游戏目录、删掉了存档文件夹时会出现）。

## 下拉框展开(2026-10-02)

下拉不再是 CustomTkinter 自带的那张 ``tk.Menu``(Tk 菜单没有"最大高度"选项, 内容多会一路
撑出软件窗口), 而是自建浮层(见 ``ui/dropdown.py`` 与 PLAN 27):

* **最多 10 行**, 再多加滚动条 —— 内容永远不撑出窗口;
* **按位置决定方向**: 下方放得下往下展开, 放不下而上方放得下就向上; 两边都不够时取空间大
  的一侧, 并把行数压到放得下的行数;
* 宽度至少与控件同宽, 内容更宽就跟着放宽, 但不越出窗口右边界;
* 当前值打开即高亮并滚到可见; 点一行 = 选中 + 收起; 点窗口别处 / Esc / 再点箭头 / 换一个
  下拉都会收起。

浮层用原生 ``tk`` 控件画(临时层不在 CTk 窗口链上), 颜色仍取自控件所在窗口的调色板。
它不用 ``<FocusOut>`` 收起: ``overrideredirect`` 的临时窗口抢到焦点后可能被立刻还回去,
那样会"一开就收"(见 PLAN 27.2)。

补充(2026-10-03): 超出上限时右侧会立一条**看得见**的滚动条 —— 滑块用 ``text_muted``、
轨道用 ``panel``(与轨道对比度 ≥ 3:1), 而不是 CTk 滚动条那一档暗色。浮层上的暗色滑块看着
就像"没有滚动条", 用户会以为后面没内容了。另外滚动条必须与列表**同容器**且在列表**之前**
占位, 否则会被 ``expand`` 的列表吃光, 分到 0 宽/0 高。

再补充(2026-10-03): 滚动条直接换成 CustomTkinter 原生的 ``CTkScrollbar``(形状/圆角/悬停/宽度
都与软件里其它滚动条一致), 不再自建 —— 它在普通 ``tk`` 临时窗口里也能拿到正确的 DPI 缩放。
颜色仍按浮层自己的调色板取(底色 ``panel``、滑块 ``text_muted``), 保证"看得出有滚动条"。

另: 宿主窗口被最小化/隐藏时浮层会一起收起(接了宿主的 ``<Unmap>`` / ``<Iconify>``)—— 它是独立
窗口, 不然会飘在屏幕原处。

再补充(2026-10-03, 附图反馈): 浮层现在是**宿主窗口的附属窗口**(``transient``), 不再用
``-topmost`` —— 所以点击别的程序时它会随本软件一起沉下去, 不会永远盖在最前面; 最小化本软件时
它也会跟着消失。窗口被移动/改尺寸时浮层**跟着控件重算位置**(不再停在旧坐标上盖住旁边的程序)。
"能不能和原生组件结合"这条走不通: 原生下拉是 ``tk.Menu``, 而 Tk 菜单没有"最大高度"这个选项,
限高 + 滚动条只能靠自建浮层(见 PLAN 27 / 31)。

再补充(2026-10-03): 列表**装得下**的时候滚轮不起作用 —— 之前滚轮会把只有四项的"每页"滚走一行,
最上面那项被滚出视野、底下空出一行(附图反馈)。装得下就不该有"滚动"这回事; 真的超过上限、右侧
立起滚动条时才让滚轮/滚动条生效。打开时另外把视图归零一次, 免得构建期(当时列表只有一行高)
留下偏移。
