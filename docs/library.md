# 游戏库：统一主页与本地游戏发现

主页是主窗口内的一个页面，也是软件打开后默认显示的页面：游戏变多以后"哪些游戏需要处理"比"某个游戏有哪些备份"更常用，因此先给全局视图，需要时再进入某个游戏的详情页。

备份、恢复与定时任务的行为见 [features.md](features.md)，各平台的探测来源差异见[platforms.md](platforms.md)。

## 主页结构

- 主页分两个分区（顶部页签切换）：**游戏库**（默认）与**游戏发现**；两者共用同一份数据—— 在发现分区导入一款游戏后，切回游戏库就能看到它。
- 游戏库从上到下依次是：视图页签（**全部游戏 / 最近活跃 / 待处理 / 已归档**，带数量）+ 平台/类型下拉框（每项也带数量，数量为 0 的分类不会出现）+ 名称搜索（回车或"搜索"生效，"清除"复位）→ **展示方式**开关 + 选中行的动作按钮 → 游戏列表 → 底栏计数与分页控件。
- 动作作用于选中行：**打开详情**（切到该游戏的详情页）、**立即备份**、**添加存档位置**、**修正路径**（打开游戏管理窗口）、**编辑标签**（逗号分隔，最多 6 个、每个 16 字）、**归档/取消归档**。归档不是删除：记录、备份与存档位置都保留，随时可以取消。
- **启用/停用**：**同一时刻只允许一款游戏处于启用状态**，新建的游戏默认停用；点「启用」后，原本启用的那款会自动停用（也可以先「停用」让自己先空着），只有启用且未归档的游戏才响应全局快捷键与定时备份。
- **归档后只剩四项功能**：删除游戏（在游戏管理窗口里，按钮此时改名为「删除游戏」）、导出游戏、取消归档、打开详情；其余按钮一律置灰。归档同时会把该游戏停用并暂停它的定时备份。

## 列表与海报

- **列表模式**按列对齐展示每款游戏的核心摘要：名称、平台、存档位置数、备份数、最近备份时间、最近活动时间与状态标签（平台、是否已备份、是否来自探测、风险、归档与自定义标签）；存档路径不可用时把状态标签标红。列表按"待处理在前 → 最近活动倒序 → 名称"排序。
- **列表的宽度分配**：除名称外都是长度可预期的内容（平台名、数字、时间、状态标签），它们宽度固定并**整块贴靠界面右侧**；剩下的宽度全部给名称，因此**窗口拉宽就能多看到几个字**（名称过长时仍在行末补省略号）。表头随窗口宽度自动与数据行对齐。
- **海报模式**用卡片展示：**竖屏封面**（优先用本地缓存的商店封面，没有缓存或解码失败时回落为游戏名前两个字；封面右下角是当前备份数量角标）、游戏名称与最近活动时间；卡片固定尺寸并按窗口宽度自动决定每行张数（收窄时至少两列），网格**从左上角开始排列**（列不分配剩余宽度，卡片不会被挤到行中间）。列表模式的行头像优先显示缓存**图标**（从封面裁出的方形图，不是平台那带标题的艺术字图），没有图标才回落彩色圆点。
- **分页显示**：底栏右侧是"每页 + 第 x/y 页 + 上一页/下一页"，**每页条数可选30（默认）/60/100/200**；不需要翻页时上一页/下一页会自动置灰。
- **名称很长时不会挤坏布局**：名称是唯一长度无法预期的一列，它拿的是"剩下多少算多少"的宽度（见上一条），超出就补省略号；海报卡片里的名称最多折两行（卡片尺寸不变）。全文仍可在游戏详情的"游戏设置 / 重命名"对话框里看到和修改。

## 分类与筛选

- **待处理**只包含真正卡住不能用的游戏：**还没有配置存档位置，或者存档路径已失效**；已经配好可用位置但还没备份过的游戏不算待处理（它随时可以备份），这类状态由"未备份"与"长期未更新"分类表达。"最近活跃"= 14 天内有备份或变更。
- 从探测结果导入的游戏会带上来源平台（Steam/Epic/GOG/Ubisoft Connect/监控目录/手动），导入后在主页的"平台"筛选中即可区分；路径风险、备份与活动时间每次进入主页都会重新计算。
- 视图、平台、分类、搜索词与展示偏好（列表/海报、每页条数）都保存在数据库的 `home_state`表（单行，带格式版本号）：关掉软件再打开仍是上次看到的样子；自定义标签与归档标记存在`games` 上，属于业务数据。旧版本（格式不同）的记录会被忽略并回落到默认值，而不是让界面读到无法解释的取值。
- 切换浅/深主题时主页会用新调色板重建一次（主页控件是按调色板逐一定色的），当前分区、筛选条件、页码与选中项都会保留。

## 本地游戏发现

主页的"游戏发现"分区就是本地游戏探测，内部分为"探测结果"与"监控目录"三个页签（**默认停在探测结果**），右上角固定是"重新扫描"。

### 探测结果

- 按平台扫描本机的平台安装清单、Windows 注册表与监控目录，把发现的游戏列为待确认的候选。
- **探测结果不会自动进入游戏库**：只有点"导入为游戏"才会新建游戏记录（探测到的是安装目录而不是存档目录，因此**不会自动登记成存档位置**）；也可以"忽略"（之后扫描不再提示，可随时恢复）或"修正路径"。
- 列表**默认只看"待处理"**（这个页面的用途就是把发现的游戏收进游戏库），可切换全部/已导入/已忽略；筛不到内容时给出的是该筛选下的空状态与各状态数量，而不是笼统的"暂无探测结果"。
- 路径缺失、不是文件夹、不可读或属于高风险位置时给出明确状态（候选显示为不可导入）；游戏被卸载后再次扫描会刷新该状态，而用户的"已忽略/已导入"决定不会被覆盖；与游戏库同名的候选会自动标记为"已导入"。
- **平台官方工具默认隐藏**：包里那份 `excluded-games.json`（在 `resources/` 下，**开发人员手工维护的默认单行紧凑 JSON**，程序只读不写，也不会因为用户手动忽略了某个程序就自动追加条目）列着公共运行库、录制工具这类“本身不是游戏”的程序；扫描时按“平台 + AppID / 名称 / 名称前缀”匹配，命中且仍待处理的候选直接标成**已忽略**（就是界面上的隐藏状态，可在“已忽略”筛选里恢复），摘要里也会写“平台工具已隐藏 N 项”。清单只影响新发现与仍待处理的候选，不会推翻你已经导入或忽略过的决定。
- 单个来源出错（注册表不可读、清单损坏）只影响该来源：探测异常写入日志并在摘要里计数，结果摘要（参与扫描的监控目录数、新增/更新数量、不可用路径数）显示在分区底部，手动添加游戏与存档位置始终可用。

### 监控目录

- 用于覆盖平台客户端路径自定义或非平台游戏的情况：目录下的每个子文件夹都当作候选游戏（目录里没有子目录时把目录本身当作候选）。
- 添加/编辑会校验路径存在、是文件夹、可读取，并拒绝盘符根目录与用户主目录，重复目录直接拦下。
- 每行显示实时路径状态（可用/不存在/不是文件夹/不可读/高风险）与上次扫描时间，支持添加、编辑、启用/停用与删除；停用只是不参与扫描，不会删除记录。

### 存档路径推断（已并入探测结果）

- **一探测游戏就推断**：该游戏的安装目录一路进探测结果时，前端就会问一次平台模块“这款游戏的存档在哪”，把拿到的路径直接列在那一行下面（路径 + 危险标记）。路径本来就来自平台清单/云端清单这类可信渠道，所以不再标可信度；需要提醒的只有危险目标。推断不出来或平台不支持，行里也会说清楚是哪种情况。
- **导入时才落库**：点“导入为游戏”会弹出对话框，里面就是刚才推断出的路径，每条都能改、能取消勾选，也能自己加一条；每条路径后面还有“浏览…”按钮，点开就是系统目录选择框（与游戏详情里添加/修改存档位置同一个），也可以可视化挑目录。确认后这些路径才写进该游戏的存档位置（与平台候选一致的那条保留“来自哪份清单”的来源，自己改的/新加的记成手动添加），危险路径会被校验拦下。
- **封面与图标在导入之后才探测**：导入成功后开始后台取图，并在左下角状态栏提示“已导入… · 开始尝试探测封面与图标”；取图同样要平台模块支持，不支持则什么都不做。补图完成会抬高数据版本，主页与详情页会自动重绘，图标随后自己出现（不需要手动刷新）。
- **删除游戏会连缓存一起清掉**：封面与图标属于可再生的派生数据，删游戏时一并删除；下次同 AppID 重新导入会重新探测，不会误用旧图。
- 平台能力由适配器声明（`supports_save_paths` / `supports_artwork` / `artwork_refs`）：Steam 全支持，Epic/GOG/Ubisoft 与监控目录走“不支持”的降级，界面明说需要手动添加。
- 危险判定只管“整个游戏安装目录”：`<安装目录>\saves` 这类子目录是合法存档位置，予以放行；只有候选**就是**安装目录、或**包含**安装目录时才算危险（那两种情况恢复/删除会动到游戏本体）。盘符路径的大小写不敏感（`D:\Steam` 与 `d:\steam` 视为同一处）。

## 界面细节

界面统一修了"描边看不见"的两类问题：

- **CustomTkinter 会把绘制尺寸向下取整到偶数**，宽或高为奇数的控件最右一列/最下一行不会上色（看起来就是右边框、下边框丢了）。`archive_management/ui/rendering.py` 在引擎层面关掉了该取整（库自己在分隔按钮里也是这么做的）。
- **贴边的子控件用底色盖住了 1px 描边**（典型是卡片里最后一行文字），现在卡片都会留出内边距，分区内的内容内缩也统一成与游戏库相同的值。

回归用例在 `tests/integration/test_gui_layout.py`（遍历真实窗口控件树，断言没有容器被贴边 G子控件盖住下边/右边）与 `tests/unit/test_ui_rendering.py`。
